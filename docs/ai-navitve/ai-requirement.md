# AI Native 开发工程师 笔试题

实现一个 AI 文本处理应用，提供中译英、英译中、文本总结三个功能。
大模型调用可使用任意 API（OpenAI / DeepSeek / 智谱等），若无 Key 可使用伪代码或本地模拟，但需保留真实调用链路。
代码上传至 GitHub/Gitee，答案提交仓库地址（提交一周后可删除）。

## 一、基础要求

### 1. 前端实现

- **1.1 功能交互界面**
  - 列表页：展示所有可用功能，用户可点击进入对应功能页面。
  - 翻译页：文本输入、语言方向选择、结果展示区。
  - 总结页：长文本输入、字数/要点数控制、结果展示区。

- **1.2 流式请求逻辑**
  - 支持取消进行中的任务（前端发取消请求，后端终止执行）。
  - 调用后端 SSE 接口，结果逐字/逐句渲染，模拟打字机效果。
  - 支持停止生成（中断流式连接）。

### 2. 后端实现

- **2.1 接口设计**

  - `GET /api/functions` —— 返回所有功能列表及描述。
  - `POST /api/task` —— 提交任务（传入功能类型、参数），SSE 流式返回 taskId 和任务结果。
  - `DELETE /api/task/{taskId}` —— 取消任务。

- **2.2 流式响应**
  - 后端通过 SSE 将模型输出的 token 逐块推送给前端。
  - 若任务已执行完毕，则一次性流式推送完整结果。

### 3. CLI 与 Agent 工具链

- **3.1 CLI 调用**

  编写一个命令行工具（Python/Go/Node 均可），能够直接调用后端服务完成一次翻译或总结，示例：

  ```bash
  ai-app translate --text "Hello" --from en --to zh
  ai-app summarize --text "长文本..." --max-points 3
  ```

- **3.2 skill.md**

  编写 skill.md，描述如何通过这个 CLI 工具被 OpenClaw/Claude Code 等 Agent 识别并调用。需给出 Agent 调用的截图，证明工具可被 Agent 发现并执行。

## 二、加分项

### 1. Vibe Coding + SDD/TDD 开发流程

使用 AI 编程工具开发，遵循规范驱动开发（SDD）或测试驱动开发（TDD）。仓库中需包含：

- `agent.md` —— 描述 AI Agent 在本项目中承担的角色、协作方式。
- `spec/` 目录 —— 含需求拆分、接口设计、页面原型等规范文件。

### 2. 全栈深度

- 前端：虚拟滚动优化大文本输入、流式渲染性能优化、深色/浅色主题切换、响应式布局。
- 后端：请求参数校验、统一错误处理、日志追踪、任务超时控制。

### 3. 异步任务与轮询

- 前端轮询任务状态（pending / running / done / failed），展示进度反馈。
- 后端使用任务队列（内存队列 / Redis / Celery 均可），任务提交后异步执行。
- 大模型调用写入结果，并更新任务状态。

### 4. 数据闭环

记录每次调用的用户输入、模型输出、耗时、状态，并提供简单查询页面。

### 5. Docker 支持

提供 Dockerfile 与 docker-compose.yml，可一键启动前后端服务。

## 三、技术栈建议

- 前端：React/Vue + TypeScript，可以使用 Vite 或 Next.js 全栈构建。
- 后端：Python (FastAPI) 或 Go (Gin) 均可，选用自己熟练的。
- 大模型：任意 API，伪代码模拟需注释清楚。
- CLI：Python 的 click，Go 的 cobra，Node 脚本。
